ilife of an actionpp. 02–03

From human will to a signed receipt, in six steps.

An action begins in a human and ends in a record. Between the two: passport, delegation, intent, gateway, enforcement, receipt — six checkpoints, all signed.

Every act an agent performs traces back, in principle, to a person. The system makes that traceability literal. A passport — an Ed25519 keypair bound to a human principal — sits at the root. From there, the human signs a delegation that lists what an agent may do, and only what an agent may do.

The agent then issues an intent: a precisely-shaped ask that names the tool, the target, and the budget. The gateway evaluates that intent against fourteen distinct constraints. If any check is missing or ambiguous the gateway denies. Permitted actions execute on a rail adapter, and the entire transit is captured in a canonical receipt.

scopeEach delegation narrows tools, budget, services. Monotonic — never expands.

iidelegation & cascadepp. 04–05

Authority can only narrow.

A child scope is a strict subset of its parent. Revoke any node, and the entire subtree dies — fail-closed at the gateway, in one call.

Delegation is the protocol's load-bearing idea. A human signs a passport. That passport signs a delegation to an orchestrator agent. The orchestrator signs a sub-delegation to a worker. At every step the new scope is checked against the previous: tools removed are gone forever; budgets only ever go down; allowed merchants only ever shorten.

Because delegations form a tree, revocation is a single operation. Issue revoke(agentId) and the gateway refuses every descendant on the next request — fail-closed, with no cache or ambiguity to slip through.

narrowStrict subset, enforced at issuance. The chain rejects expansions.
cascadeOne API call — the entire subtree denies on next attempt.

iiigateway judgementpp. 06–07

Fourteen checks. No bypass.

Every action is evaluated against fourteen constraint dimensions. A missing check is a denial. There is no fallback, no soft-pass, no cache leak.

The gateway is intentionally boring. It ingests a signed intent, walks a fixed list of fourteen dimensions, and emits either an authorization or a contestable denial. The list is short enough to enumerate in a footnote and long enough to encode every constraint a real-world deployment has needed so far.

Conformance is governed by a public test suite of thirty-seven plus ten vectors, run on every commit across six implementations. The list is intentionally not extensible at runtime — a gate added in production is treated, by the suite, as a missing gate.

14 dimensionsidentity, signature, scope, budget, rate, values, reputation, freshness, +6 more.

ivthe trust meshpp. 08–09

A graph that terminates in people.

Agents, humans and services bind to one another through signed delegations and receipts. Reputation is earned by completed work — never declared.

Zoom out far enough and the protocol becomes a graph. Nodes are passports — sometimes a human's, more often an agent's. Edges are signed delegations, settled receipts, and Merkle-proven mutual-auth handshakes (the four-step downgrade-proof variety, version one of which shipped on the twenty-second of April).

Every chain of edges, however long, terminates at a human principal. That is the property the system most jealously defends. An agent without a human at the end of its chain is, by definition, unable to act.

vpayment railspp. 10–11

Pay narrowly, settle openly.

Five rails — x402, AP2, ACP, MPP, Stripe Issuing — share one scope check. The agent pays under cap; the merchant receives a signed settlement record per period.

Money is the place where soft norms become hard. The protocol does not invent a rail; it stands behind the rails the world already uses, and bolts a single, sharp check between the agent and the rail adapter. Spend cap. Merchant allow-list. Single-use intent. Three constraints, evaluated together, on every transaction.

What the merchant receives, in addition to funds, is a signed period record — produced by the Build C pipeline (16 April) and settled at every period boundary regardless of disputes. This is what makes the system auditable in the boring sense: an accountant can ask for a number, and there is a number.

vicross-impl interoppp. 12–13

Six implementations, one hash.

A canonical fixture, run through six independent codebases and eight independent canonicalizers, must produce the same SHA-256. If it doesn't, the suite fails — the spec, not the code, is wrong.

Interop is asserted, not assumed. The conformance suite holds a canonical input — CTEF v0.3.2, section A — and a target hash. Six independent implementations (qntm, AgentGraph, Foxbook, AgentID, Nobulex, ArkForge) and eight independent canonicalizers must converge, byte-for-byte, on the same digest.

This is the guarantee that survives any one implementation. If a vendor's library drifts, the suite catches it; if the spec under-specifies, multiple vendors disagree and the suite catches that. It is the protocol's slowest-moving and most public commitment.
